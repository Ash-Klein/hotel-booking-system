## 3. 每屏说明

### 01 首页搜索
**目标**：让顾客在 3 步内发起查房。
**布局**：品牌头部 → 搜索卡（城市/日期/人数）→ 快捷筛选 → 附近酒店卡片 → 底部 Tab。
**关键状态**：酒店卡片显示"仅剩 3 间/5 间"，把库存紧张前置到列表页。
**交互**：修改城市/日期/人数 → 查空房 → 房型报价。
**理由**：搜索是主路径第一步，日期与人数必须同屏；余量提前露出，减少点进去才发现无房。

### 02 房型报价
**目标**：让顾客快速比较房型与总价。
**布局**：酒店信息 → 日期条 → 筛选 → 房型卡（图片/描述/余量/标签/单价/总价/订）→ 住客点评 → 底部总价栏。
**关键状态**：仅剩 2 间、仅剩 1 间、可取消、含双早。
**交互**：筛选 → 订 → 填单。
**理由**：每晚价与"2 晚总价"同时给，避免顾客自己算；点评补决策信心。

### 03 填单锁房
**目标**：在锁房倒计时内完成入住人填写并进入支付。
**布局**：倒计时头部 → 锁定提示条 → 入住人表单 → 订单信息与价格明细 → 预订须知 → 底部支付栏。
**关键状态**：14:32 倒计时持续可见；字段校验失败时保留已填内容（REQ-051）。
**交互**：填写 → 去支付；超时自动释放。
**理由**：倒计时放在头部而不是角落，降低"填到一半房没了"的焦虑。

### 04 支付
**目标**：一次完成支付，减少误付。
**布局**：待支付金额 → 支付方式（微信/支付宝/银行卡）→ 支付安全 → 订单摘要 → 底部实付。
**关键状态**：默认选中微信；金额与订单摘要同屏核对。
**交互**：切换方式 → 确认支付 → 支付结果。
**理由**：支付页最怕"付错金额/付错单"，所以把订单摘要放在按钮上方。

### 05 订单改退
**目标**：让顾客自助完成改期/取消，减少客服。
**布局**：状态卡 → 房型与入住人 → 订单进度时间轴 → 取消规则 → 修改/取消 → 联系酒店/客服。
**关键状态**：已确认待入住；24 小时内外不同违约金。
**交互**：修改订单 → 改期/改房型；取消订单 → 退款预览。
**理由**：规则放在按钮之前，避免"点了取消才知道扣钱"。

### 06 今日工作台
**目标**：前台一屏看清今天要接待谁、谁要退房、哪里出问题。
**布局**：4 个 KPI → 今日到店表 → 待处理异常 → 快捷操作。
**关键状态**：待入住/已确认/异常；房号显示"待分配"，与 REQ-025 一致。
**交互**：办理入住 → 右侧抽屉；处理异常 → 异常详情。
**理由**：前台是高频扫视场景，表格密度高于卡片；异常单独成卡，避免被正常订单淹没。

### 07 库存与房价
**目标**：店长按日维护价格与库存，并处理关房/协议锁房。
**布局**：房型与月份工具栏 → 4 个概览 → 7 日×5 房型日历 → 图例。
**关键状态**：可售（绿）、≤2 间（橙）、满房（红）、协议锁定（紫）。
**交互**：点单元格 → 调价/关房/锁房；批量调价。
**理由**：日历热力图能一眼看出周末与展会的供需；协议锁房必须与普通库存同屏可见。

### 08 订单检索与入住
**目标**：前台用订单号/手机号/姓名快速定位并办理入住。
**布局**：搜索栏 → 状态 Tab → 订单表 → 右侧入住抽屉（证件、分房、押金、备注、确认）。
**关键状态**：待入住/异常/已入住；本门店范围提示。
**交互**：检索 → 选中订单 → 核验 → 分房 → 确认入住并制卡。
**理由**：抽屉保留列表上下文，前台不用在页面间跳转。

### 09 门店与房型
**目标**：集团统一维护门店与房型，门店只读。
**布局**：门店表 → 右侧详情（档案、房型参数）→ 权限提示。
**关键状态**：营业/筹备/停业；直营/加盟。
**交互**：新增门店、编辑档案、查看房型参数。
**理由**：把"门店无房型编辑权限"直接写在详情里，权限边界可见，减少误操作。

### 10 经营报表
**目标**：集团与城市经理看经营结果并对账。
**布局**：城市/月份/类型筛选 → 4 个 KPI → 出租率趋势 → 城市排行 → 门店明细。
**关键状态**：T+1 更新；直营+加盟可分开。
**交互**：筛选 → 下钻门店 → 导出 Excel。
**理由**：从宏观 KPI 到城市排行再到门店明细，符合"先看异常、再定位"的分析路径。

### 11 权限与审计
**目标**：配置六类角色权限，并追溯关键操作。
**布局**：角色权限矩阵 → 角色说明（城市经理只读）→ 最近操作日志。
**关键状态**：✓ 允许 / — 拒绝；城市经理仅"查看报表"。
**交互**：勾选权限、查看日志、按角色筛选。
**理由**：矩阵比逐个角色点开更直观；城市经理列单独说明"只读 + 按城市过滤"。
